# Сайт лёг? Пусть Claude сам прочитает логи

> 🇬🇧 English version: [README.en.md](README.en.md)

Учебный проект к ролику: маленький сайт со страницей входа, который **специально сломан**.
Вы научитесь не искать ошибку руками, а поручать это Claude Code: он сам читает логи,
находит причину и предлагает исправление — вам остаётся только нажать «да».

**Время:** 10–15 минут. **Нужно:** компьютер (macOS, Windows или Linux), Python 3.9+, Claude Code.

---

## Шаг 0. Что понадобится

1. **Python 3.9 или новее.** Проверить: откройте терминал и введите `python3 --version`
   (на Windows — `python --version`). Если команды нет — скачайте Python с [python.org](https://www.python.org/downloads/).
2. **Claude Code** — Claude, который работает прямо в терминале и умеет читать и править файлы проекта.
   Нужна подписка Claude (Pro или выше) или API-ключ Anthropic.
   Установка — по официальной инструкции: <https://code.claude.com/docs/en/setup>.
   Проверить, что установлен: `claude --version`.

## Шаг 1. Скачайте проект

```bash
git clone https://github.com/mishabor255-collab/claude-logs-demo.git
cd claude-logs-demo
```
Нет git? Нажмите на GitHub зелёную кнопку **Code → Download ZIP**, распакуйте и откройте папку в терминале.

## Шаг 2. Запустите сайт и убедитесь, что он сломан

```bash
python3 app.py
```
Откройте в браузере <http://localhost:8000>, логин `demo`, пароль `demo123`, нажмите **Войти**.
Вы увидите красное «**Что-то пошло не так**». Сайт лёг. 😱

Остановите сайт: в терминале **Ctrl + C**.

## Шаг 3. Попросите Claude найти причину

В той же папке проекта запустите Claude Code:
```bash
claude
```
и напишите ему обычными словами:
```
Сайт падает при входе. Найди в логах, почему не работает вход, и исправь.
```

Что произойдёт:
1. Claude сам откроет `logs/app.log` и увидит ошибку `KeyError: 'DATABASE_URL'`.
2. Поймёт, что в файле настроек `.env` не хватает строки `DATABASE_URL` (а в `.env.example` она есть).
3. Предложит добавить её и **спросит разрешения** — посмотрите, что он меняет, и согласитесь.

> Claude Code всегда спрашивает, прежде чем менять файлы или запускать команды. Читайте, что он предлагает, — это хорошая привычка.

## Шаг 4. Проверьте

```bash
python3 app.py
```
Снова войдите `demo / demo123` — теперь вы увидите зелёное «**Добро пожаловать, demo!**». 🎉

## Почему это работает и как применять в своих проектах

- **Логи — лучший источник правды.** Ошибка почти всегда уже записана, просто её неудобно читать глазами.
  Claude прочитает длинный лог за секунды.
- **Давайте контекст.** Скажите, *что* сломалось и *где* искать: «падает вход, смотри logs/app.log».
- **Просите сначала объяснить.** Перед правкой полезно спросить: «Объясни причину простыми словами, ничего не меняй».
- **Проверяйте результат.** Запустите проект после правки и убедитесь, что всё работает.
- **Не храните секреты в git.** Здесь `.env` лежит в репозитории только ради примера. В настоящих проектах
  добавляйте `.env` в `.gitignore`, а в репозиторий кладите `.env.example` без настоящих паролей.

### Ещё запросы, которые пригодятся
```
Объясни простыми словами, что написано в последней ошибке в логах.
Найди все ошибки в logs/ за сегодня и сгруппируй их по причинам.
Сделай так, чтобы при отсутствии настройки сайт писал понятную ошибку, а не падал.
```
